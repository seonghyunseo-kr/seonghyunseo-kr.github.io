## Project Files (`_projects/`)

Each file is numbered `(N) slug.md`. The front matter schema is:

```yaml
---
name: "Project Title"
category: "Industry — Company Name"   # or "Research — Lab Name"
track: "Industry"                      # or "Research"
topic: "ML technique / domain"
period: "Mon YYYY – Mon YYYY"
year: "YYYY"
style: border
color: primary                         # primary | secondary | success | danger | warning | info
tools: [Tool1, Tool2, Tool3]
image:                                 # optional: path to image
external_url:                          # optional: external link
featured: true                         # true | false
# --- i18n fields (added by AI pipeline) ---
summary_en: ""                         # 2–3 sentence EN summary (AI-generated)
summary_kr: ""                         # 2–3 sentence KR summary (AI-generated)
name_kr: ""                            # Korean project title (AI-generated)
---
```

Body sections (Markdown):
- `## Overview` — context, goal, outcome
- `## My Contributions` — bullet list of what I did
- `## Tech Stack` — tools used

## Planned Features

### 1. AI Summary Generation (`scripts/summarize_posts.py`)

- Reads all `_projects/*.md` files
- Calls Anthropic API (`claude-sonnet-4-6`) to generate:
  - `summary_en`: 2–3 sentence English summary
  - `summary_kr`: 2–3 sentence Korean summary
  - `name_kr`: Korean project title
- Writes results back into each file's front matter
- **API key**: read from environment variable `ANTHROPIC_API_KEY`
- Run manually before committing: `python scripts/summarize_posts.py`

### 2. KR / EN Language Toggle

- A KR/EN button lives in `_includes/navbar.html`
- Language preference stored in `localStorage` (`lang: 'en' | 'kr'`)
- On toggle, JS swaps elements with `data-lang-en` / `data-lang-kr` attributes
- Affected fields: `name`, `summary`, project card body
- Static fields (tools, period, category) stay in English

## Key Conventions

- **Do not edit `_site/`** — it is auto-generated by Jekyll
- Project filenames must start with `(N) ` for ordering; Jekyll slugifies the rest
- `_data/*.yml` files drive About/Academic sections — prefer editing YAML over HTML
- SCSS overrides go in `_sass/_theme.scss` or a new `_sass/_custom.scss`
- External URLs open in new tab (`open_new_tab: true` in `_config.yml`)
- Blog posts use categories defined in `_data/blog-categories.yml`
